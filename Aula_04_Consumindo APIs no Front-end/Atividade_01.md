# Aula 04 — Atividade 01: projetos que consomem APIs

## Objetivo e método

Foram analisados dez repositórios públicos para identificar o framework usado e as APIs chamadas pelo projeto. A stack foi conferida nos manifestos (`package.json` ou configuração equivalente) e a integração foi verificada nos arquivos-fonte indicados em cada linha.

Esta é uma análise documental dos arquivos públicos do GitHub. Os projetos não foram clonados nem executados localmente; portanto, a tabela não certifica builds, deploys ou disponibilidade atual dos serviços. Os links de evidência apontam para o snapshot consultado.

## Observações da comparação

- Google Books aparece em implementações Angular, React e Next.js; a comparação mostra diferenças na organização dos clientes HTTP, no tratamento de erros e na paginação.
- Open-Meteo é usado por dois projetos Next.js. No `Local Weather`, o manifesto inclui o SDK `openmeteo` e o acesso é centralizado por um serviço integrado ao RTK Query.
- Nem todos os dados de um projeto vêm de uma API: no Autocomplete Demo, por exemplo, a lista é local e somente os detalhes são buscados na PokéAPI.
- Uma dependência ou um README, isoladamente, não comprova que uma chamada funciona. O caso NASA APOD foi marcado como não validado porque a montagem da URL observada no código aparenta estar incorreta.
