1 · Introdução e método

Contexto e objetivo

1.1 Introdução

Interfaces web que precisam responder a formulários, filtros e dados atualizados podem se tornar difíceis de manter quando estrutura, estado e manipulação do documento ficam misturados. React organiza a interface em componentes e descreve, de forma declarativa, o que cada componente deve exibir para determinado conjunto de propriedades e estado. A biblioteca é mantida em código aberto pela Meta e por uma comunidade de colaboradores. Seu escopo principal é a construção de interfaces; a aplicação normalmente combina React com outras ferramentas para roteamento, compilação e integração com serviços.

O objetivo deste relatório é explicar as características técnicas de React, discutir seus benefícios e limites, identificar cenários de uso compatíveis e relacionar esses conceitos a um exemplo que já existe neste repositório: o gerenciador de notas desenvolvido com React e Vite.

1.2 Método e delimitação

A análise foi realizada por consulta à documentação oficial de React e Vite e pela leitura estática dos arquivos do projeto de notas. Portanto, o exemplo documenta a estrutura e os fluxos observáveis no código; este relatório não afirma que o projeto tenha sido compilado, testado em produção ou submetido a uma avaliação de mercado.

O foco está no front-end. A API Express e sua persistência são tratadas como dependências externas: o cliente envia requisições HTTP, mas não controla como o servidor armazena os registros.

1.3 Biblioteca e ecossistema

Embora seja comum chamar React de framework em conversas sobre desenvolvimento front-end, tecnicamente React é uma biblioteca para interfaces. Essa distinção importa: React oferece componentes, renderização e mecanismos de interação, mas não obriga a adoção de um roteador, um formato de pastas ou uma camada específica de comunicação com APIs. A liberdade permite adaptar a solução; em contrapartida, exige escolhas explícitas e consistentes do projeto.

Decisão de escopo: React foi escolhido porque já é usado na aplicação de notas deste repositório; assim, os conceitos discutidos podem ser relacionados a código existente, em vez de a um exemplo hipotético.

2 · Características principais

Características técnicas do React

2.1 Componentes e JSX

A interface é decomposta em componentes reutilizáveis, normalmente funções JavaScript que retornam JSX. JSX permite descrever a estrutura próxima ao HTML e inserir expressões JavaScript entre chaves. A sintaxe é transformada pelo processo de build; não é HTML nem uma nova linguagem executada diretamente pelo navegador. A composição de componentes ajuda a separar partes da interface, como formulário, lista e cabeçalho, conforme o produto evolui [1].

2.2 Propriedades, estado e eventos

Props transportam dados do componente pai para o filho. Estado representa informação que pode mudar com a interação do usuário ou com respostas do sistema. O Hook useState associa um estado a um componente e fornece uma função para atualizá-lo. Eventos declarados em JSX — por exemplo, onClick e onChange — conectam ações da interface a essas atualizações. O fluxo resultante é declarativo: o componente descreve a tela a partir do estado atual [2].

2.3 Renderização, listas e efeitos

Quando props ou estado mudam, React renderiza novamente a descrição do componente e aplica as atualizações necessárias ao DOM. A reconciliação compara as árvores de elementos; a noção de Virtual DOM é uma forma de explicar essa etapa, mas não deve ser interpretada como garantia de que React será sempre mais rápido em qualquer aplicação. Em listas, a propriedade key oferece uma identidade estável para cada item e auxilia React a acompanhar inserções, remoções e reordenações.

O Hook useEffect permite sincronizar um componente com sistemas externos, como uma API ou uma assinatura. A documentação recomenda distinguir esse tipo de efeito de ações iniciadas por eventos e evitar efeitos desnecessários [3].

3 · Vantagens e limitações

Benefícios e custos da adoção

3.1 Vantagens

  • Composição: componentes podem encapsular partes da interface e ser reutilizados sem duplicar o mesmo markup em todas as telas.
  • Atualização previsível: o estado fica explícito no componente; uma interação pode atualizar os dados e fazer a interface refletir o novo estado.
  • Ecossistema: há documentação, ferramentas e bibliotecas comunitárias para necessidades que ficam fora do núcleo, como roteamento, testes e integração com APIs.
  • Flexibilidade de adoção: é possível compor a UI com ferramentas compatíveis com o tamanho e os requisitos da aplicação.
  • Reuso entre plataformas no ecossistema: conceitos de composição também aparecem em ferramentas como React Native, que é uma tecnologia separada para aplicações nativas.

Essas vantagens não dispensam planejamento. Componentes demasiadamente grandes, estado duplicado ou efeitos usados para toda transformação podem tornar a aplicação mais difícil de compreender. A documentação oficial recomenda estruturar o estado e manter o fluxo de dados claro [2, 3].

3.2 Limitações e custos

  • Aprendizado inicial: JSX, fluxo unidirecional de dados, estado e regras de Hooks exigem familiaridade com JavaScript e com a forma declarativa de programar.
  • Decisões do ecossistema: o núcleo não define sozinho rotas, acesso à API, validação, estilos ou arquitetura; bibliotecas adicionais podem aumentar manutenção e dependências.
  • Qualidade não automática: acessibilidade, responsividade, segurança de dados e mensagens de erro dependem de decisões e implementação do projeto.
  • Possível excesso de complexidade: para uma página estática simples, a configuração e o build podem custar mais do que resolver o problema com HTML e CSS.

4 · Aplicações de React no mercado

Interfaces e cenários de uso

4.1 Exemplos por domínio

React é compatível com produtos cujas interfaces atualizam conteúdo em resposta a navegação, formulários e dados recebidos de serviços. As categorias a seguir exemplificam como a composição de componentes pode contribuir; são cenários de uso, não uma pesquisa estatística sobre o mercado.

4.2 Adequação à necessidade

A escolha deve considerar a complexidade do produto, a experiência da equipe, a integração com serviços e os requisitos de renderização, além do custo de configuração e manutenção. Para páginas estáticas de baixa interação, HTML e CSS podem ser suficientes. Quando rotas avançadas, renderização no servidor ou recursos full-stack forem necessários, um framework do ecossistema React pode ser avaliado; esses recursos não pertencem automaticamente à biblioteca React.

Essa distinção ajuda a comparar tecnologias sem atribuir a React resultados que dependem de ferramentas adicionais ou da arquitetura do produto.

Limite da análise: os cenários descrevem aplicações possíveis e não indicam percentuais de vagas, participação de mercado ou superioridade universal.

5 · Exemplo prático: fluxos

Gerenciador de notas com React

5.1 Necessidade e organização

O projeto projeto_notas_front, localizado nos materiais da Aula 05, apresenta uma interface para gerenciar notas. Cada nota possui identificador, título e texto. O cliente comunica-se com a coleção /api/notes de uma API configurada na aplicação. A interface e o servidor são projetos separados; o front-end não grava diretamente no arquivo de dados do back-end.

O componente App mantém o array de notas, os valores do formulário, o identificador em edição e o estado de carregamento. No primeiro render, useEffect solicita os dados ao servidor; a resposta alimenta o estado, que passa a dirigir a lista apresentada na tela. A listagem é produzida com map e cada linha usa nota.id como chave.

6 · Aplicação prática: interface

Estado, renderização e ferramentas

6.1 Trecho representativo

const [notes, setNotes] = useState([]);

useEffect(() => {
    carregarNotas();
}, []);

// A interface é derivada do estado da coleção.
{notes.map((nota) => (
    <li key={nota.id}>
        <h3>{nota.titulo}</h3>
        <p>{nota.texto}</p>
    </li>
))}

O trecho ilustra estado, efeito de carregamento e renderização de lista com chave. No código do projeto, os botões associam eventos às rotinas de edição e exclusão; o identificador selecionado distingue criação de atualização.

6.2 Ferramentas e escopo observado

O package.json declara React e React DOM na versão 19.2.8 e Vite na versão 8.3.0. Vite fornece servidor de desenvolvimento e build para ativos de produção; não substitui React nem fornece, por si só, a lógica do gerenciador [4]. O componente raiz está em src/App.jsx, com estilos globais e locais em arquivos CSS.

A implementação demonstra operações de criação, listagem, edição e exclusão na interface. Não foi identificada uma chamada de leitura individual por ID na tela. Essa observação delimita o exemplo e não significa que uma rota da API deva ser simulada no cliente.

7 · Análise e conclusão

Resultados da análise e recomendações

7.1 Coerência da solução

Para um gerenciador de notas, React é compatível com a necessidade de atualizar a listagem e o formulário em resposta a eventos e dados recebidos da API. O exemplo torna visível a relação entre estado e renderização sem exigir que a equipe mantenha manualmente cada alteração no DOM. A combinação com Vite mantém o projeto executável por comandos padronizados, desde que Node.js e as dependências estejam instalados [4].

O exemplo também mostra decisões a revisar numa evolução. O componente concentra estado, requisições e interface no mesmo arquivo; separar formulário, item e lista poderia melhorar leitura quando o escopo crescer. Além disso, a URL da API está definida diretamente no código e os erros são registrados no console. Em um projeto ampliado, seria desejável configurar ambientes e apresentar feedback compreensível ao usuário. Essas são recomendações de evolução, não afirmações de funcionalidades já concluídas.

7.2 Critérios para uma adoção responsável

  1. Definir componentes de acordo com responsabilidades de interface identificáveis, evitando fragmentar elementos sem necessidade.
  2. Manter uma única fonte de verdade para os dados da tela e atualizar arrays de estado sem mutação direta.
  3. Usar efeitos para sincronização externa e explicitar estados de carregamento, vazio, sucesso e erro.
  4. Escolher dependências adicionais considerando manutenção, compatibilidade e necessidades reais de navegação.
  5. Verificar teclado, nomes acessíveis, contraste e adaptação a dispositivos junto com os fluxos principais.

7.3 Considerações finais

React oferece um modelo declarativo e componível para interfaces com estado e interação. Componentes, JSX, props, estado, efeitos e chaves de listas são conceitos que ajudam a organizar produtos como o gerenciador de notas analisado. A flexibilidade do ecossistema é útil, mas desloca para a equipe decisões de arquitetura e a responsabilidade por qualidade, acessibilidade e tratamento de falhas.

A escolha adequada depende do escopo. Para aplicações com fluxos dinâmicos e dados de API, React pode reduzir acoplamento à manipulação manual do DOM e facilitar evolução incremental. Para páginas simples ou equipes sem necessidade de uma camada de componentes, seu custo de configuração pode ser desnecessário. A conclusão, portanto, é contextual: o valor da biblioteca decorre de resolver as necessidades observáveis do produto, não de uma preferência universal.

Síntese: no projeto de notas, React organiza a interação da interface; Vite fornece o ambiente de desenvolvimento e build, enquanto a API permanece responsável pelos dados.
