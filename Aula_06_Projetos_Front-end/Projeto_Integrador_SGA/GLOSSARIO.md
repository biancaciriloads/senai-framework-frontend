# Glossário — Gestão do Projeto Integrador SGA

Os termos estão definidos para a atividade da Aula 6. Os marcadores distinguem o que foi encontrado no SGA do que é apenas uma sugestão.

| Termo | Significado e relação com a inspeção |
| --- | --- |
| **Backlog / Product Backlog** | Lista priorizada e revisável de necessidades do produto. **Encontrado parcialmente:** há issues e label `backlog`, além de prioridades no README; não foi encontrado um documento único que reúna e ordene formalmente todo o backlog. |
| **Issue** | Registro de trabalho, solicitação ou problema no GitHub. **Encontrado:** issues do SGA com títulos, estados, labels e, em alguns casos, milestone. |
| **Tarefa** | Unidade de trabalho concreta que contribui para uma entrega. **Encontrado:** títulos de issues como disponibilizar endpoint ou criar rota; o nível de detalhamento varia. |
| **Prioridade** | Ordem de importância/urgência para decidir o que será trabalhado primeiro. **Encontrado:** P1/P2/P3 no README e labels `urgente`, `Alta`, `Média`, `Baixa`. Não foi encontrado um mapeamento entre as duas escalas. |
| **Estimativa** | Avaliação relativa de tamanho, complexidade ou esforço, não promessa de duração. **Não encontrado como regra definida:** existem labels `PP`, `P`, `M`, `G`, mas a escala e seu significado não foram confirmados. |
| **Planning Poker** | Técnica colaborativa para chegar a uma estimativa relativa por consenso. **Sugestão:** pode ser adotada após definição de uma escala comum. |
| **Milestone** | Agrupamento de issues associado a uma etapa/entrega. **Encontrado:** milestones temáticos no GitHub do SGA. Não há evidência suficiente para chamá-los de Sprints. |
| **Sprint** | Ciclo de duração fixa com objetivo e conjunto de trabalho selecionado, usado no Scrum. **Não encontrada** como prática identificada no SGA. |
| **Kanban** | Método de visualizar e acompanhar fluxo de trabalho em colunas, limitando trabalho em progresso quando aplicável. **Não encontrado:** GitHub Projects indicava zero boards; ver proposta em [KANBAN.md](./KANBAN.md). |
| **WIP (Work in Progress)** | Limite de itens que podem estar em andamento ao mesmo tempo. **Não encontrado** como limite definido no SGA; há apenas valores sugeridos no documento de Kanban. |
| **Branch** | Linha independente de desenvolvimento no Git. **Encontrado:** `main` protegida e outras branches. Uma convenção de nomenclatura não foi encontrada. |
| **Pull Request (PR)** | Solicitação para revisar e integrar alterações de uma branch. **Encontrados** PRs no histórico público; isso não comprova uma regra global de aprovação. |
| **Critério de aceitação** | Condição verificável para aceitar uma issue ou funcionalidade. **Encontrados parcialmente:** alguns milestones descrevem critérios genéricos; não foi localizado um padrão aplicado a todas as issues. |
| **Definition of Ready (DoR)** | Condições mínimas para um item estar suficientemente claro e poder ser selecionado para trabalho. **Não encontrada** formalmente no SGA; proposta em [KANBAN.md](./KANBAN.md). |
| **Definition of Done (DoD)** | Condições acordadas para considerar um item completo, incluindo validação e evidências. **Não encontrada** como regra geral; milestones específicos contêm critérios pontuais/sugeridos. |
| **Board / Quadro** | Visão de trabalho organizada por estados, por exemplo em GitHub Projects. **Não encontrado** no repositório na data da inspeção (0 projetos abertos e 0 fechados). |
| **Deploy** | Publicação de uma aplicação em ambiente acessível. **Encontrado:** `https://sga-iota.vercel.app` no perfil “About” do repositório. |
